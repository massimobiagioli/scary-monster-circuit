# ADR-0014: Always stream the live dashboard

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

The live `Snapshot` dashboard was behind a `probe` Cargo feature (ADR-0008,
ADR-0011). A normally flashed board (`make upload-firmware`) therefore only
printed event lines, and `make logs` could not show the current value of the
sensors and actuators; you had to flash the separate probe build first. That is
the opposite of what a developer watching the prop expects from `make logs`.

## Decision

- Remove the `probe` Cargo feature. The firmware always builds the `Snapshot`
  once per second and streams it over the USB serial port alongside the log
  lines.
- `make logs` now shows the live dashboard; `make probe` becomes a convenience
  that builds, flashes, and streams it in one command.
- Drop the `FEATURES` Makefile variable and the `--features probe` build.

## Consequences

- `make logs` shows every component in real time with no special build, which is
  what the workflow needs.
- The dashboard render and the `Monitor` are always part of the firmware; they
  add a little code size and about one kilobyte per second of serial traffic,
  neither of which matters for the prop.
- There is no longer a diagnostics-free build; this supersedes the feature
  gating of the dashboard described in ADR-0008 and ADR-0011.
