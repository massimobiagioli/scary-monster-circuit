# ADR-0007: Mock-based unit tests for the whole library

- **Status:** Accepted
- **Date:** 2026-09-27

## Context

Only `state_machine.rs` and part of `audio.rs` had unit tests. The two drivers
(`sensor.rs`, `servo.rs`) and the main-loop dispatch in `src/main.rs` were
unverified, even though they hold most of the arithmetic (servo pulse widths,
echo timing) and the error handling. Hardware-free code can be tested
deterministically by replacing the pins, the clock, the PWM channel and the
UART with test doubles.

## Decision

- Add `firmware/src/lib/test_support.rs` (compiled only under `#[cfg(test)]`)
  with mocks for every hardware trait the library depends on:
  - `SensorRig`: one HC-SR04 on a shared "virtual wire". A single cell of
    virtual microseconds is read by the clock and by both pins, so a test
    only states the target distance and the driver measures it.
  - `servo_head()`: a `Head` on a `TestPwm` channel, plus a `PwmHandle` to read
    the duty cycle it was commanded to.
  - `TestPlayer` and `TestWriter`: an audio player and a byte sink that record
    what they were asked to do.
  - Every mock can be made to fail, so the error branches are covered too.
- Extract the main-loop dispatch from `src/main.rs` into
  `firmware/src/lib/controller.rs`. `Controller::update` takes a `Reading` and
  the two actuators, so the full behavior (including "play the track only when
  entering `Action`") is tested with mock actuators. `src/main.rs` keeps only
  the RP2040 wiring and the defmt logging.
- Mark the binary target `test = false` in `Cargo.toml`, because `src/main.rs`
  cannot be compiled for the host (the RP2040 crates are `arm`-only).
- Make `TURN_DEADBAND_CM` comparisons saturating, so an out-of-range reading
  (above `MAX_RANGE_CM`) cannot overflow.
- Extend the tooling: `make lint` now also lints the tests, and a new
  `make coverage` target reports line/region coverage with `llvm-cov`. Test
  code and the crate root are excluded from the report.

## Consequences

- The library is 100% covered (regions, functions and lines) by `make test`,
  and `make coverage` proves it.
- Actuator errors are still swallowed by the controller, as before, but that
  behavior is now pinned down by a test instead of being implicit.
- The behavior logic now lives in the library, so the binary is a thin adapter
  that is not compiled by the host test suite.
- Tests use only `std` (available under `cfg(test)`) plus the same
  `embedded-hal`/`embedded-io` traits as the firmware, so no new dependency is
  added to the device build.
- `make coverage` needs the `llvm-tools-preview` rustup component.
