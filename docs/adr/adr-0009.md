# ADR-0009: Project-local, pinned probe-rs tool

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

Flashing and reading logs need the `probe-rs` binary, and the docs told users to
run `cargo install probe-rs-tools`. That installs the latest version into the
global toolchain, so `make upload-firmware` depends on whatever the user happens
to have, and a fresh machine fails with `No such file or directory` until they
install it by hand. This breaks the buildability principle (reproducible
toolchain, no manual steps) and the project rule of never installing software
outside the repository.

`probe-rs-tools` is a binary-only crate (`has_lib: false`), so it cannot be
declared as an ordinary crate dependency in a `Cargo.toml`; the binary has to be
built and placed somewhere.

## Decision

- Add `tools/probe-rs/`, mirroring the Python tools: a wrapper script
  `tools/probe-rs/probe-rs` installs the pinned version into a local root
  (`tools/probe-rs/.cargo-home`) on first use and then execs it.
- Pin the version in `tools/probe-rs/version.txt` (currently `0.32.0`) and
  install it with `cargo install --locked --version <pinned> --root
  tools/probe-rs/.cargo-home`. No global install, no unversioned install.
- Point the Cargo runner in `firmware/.cargo/config.toml` at the wrapper, and
  use it in the Makefile `logs` target via the `PROBE_RS` variable, so RTT logs
  and debug-probe flashing go through the pinned tool.
- Git-ignore the local install root.

## Consequences

- A fresh checkout gets the pinned `probe-rs` on first use; the first run
  downloads and compiles it (slow once, fast afterwards).
- Flashing and logs are reproducible: everyone uses the same `probe-rs` version.
- Bumping `probe-rs` is a one-line change to `tools/probe-rs/version.txt`.
- `cargo` still uses the global registry cache for downloading; only the built
  binary is project-local.
