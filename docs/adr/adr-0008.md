# ADR-0008: Live diagnostic probe over RTT

- **Status:** Superseded by [ADR-0011](adr-0011.md)
- **Date:** 2026-10-11

## Context

All the interesting state of the prop lives on the device: the two distance
sensors, the head servo, the MP3 player and the behavior state machine. The
only channel back to a developer is RTT (`make logs`), which prints free-form
`defmt` messages. There was no single place to see the current value of every
component, and no way to spot a disconnected sensor.

## Decision

- Add a `probe` Cargo feature to the firmware. When it is enabled the main loop
  builds a [`Snapshot`] of every component once per second and streams it over
  RTT as a boxed, plain-text dashboard.
- `make probe` builds the firmware with `--features probe`, flashes it and
  attaches to RTT, so one command shows the dashboard. The default build stays
  free of diagnostic traffic.
- Put the diagnostics in a new library module, `firmware/src/lib/probe.rs`, so
  the logic is host-testable:
  - `SensorState` maps a sensor `Result` to `Distance`, `NoEcho` or `Wiring`,
    and knows the distance to feed the state machine.
  - `Monitor` counts how long each sensor has answered with no echo. A sensor
    that stays silent for `SILENT_PROBES_BEFORE_WARNING` probes (10 s at one
    probe per second) is reported as a probable fault.
  - `Snapshot` renders the dashboard into any `core::fmt::Write` sink. It has a
    "PROBLEMS" section that lists a wiring hint for each suspect sensor, for a
    failed servo command and for a failed audio command, or "none detected".
  - `FixedText<N>` is a fixed-capacity, allocation-free text sink; the firmware
    renders into a 640-byte stack buffer and prints it with `defmt`.
- Expose the last commanded angle from `Head` (`Head::angle`) and the last
  `ActuatorStatus` (servo/audio failure flags) from `Controller`, so the
  snapshot can report actuator health without changing the control behavior.

## Consequences

- `make probe` gives one clean, readable view of the whole prop and highlights
  likely wiring problems, without guessing from raw logs.
- The dashboard is not part of the shipped behavior: the `probe` feature is off
  by default and adds no allocation and no RTT traffic to the normal firmware.
- `Controller::update` now returns `None` instead of the track when playback
  fails, because a failed command did not start a track. The change is pinned
  by the mock-based tests.
- `probe.rs` is covered by `make test` like the rest of the library; the
  library stays at 100% region coverage.
