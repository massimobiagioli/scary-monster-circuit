# ADR-0018: The servo only moves when its angle changes

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

The controller commands the head on every loop: `center()` while `Idle`,
`set_angle(...)` while `Follow`/`Action`. Because the loop runs about 20 times a
second, the same duty cycle was rewritten again and again even when the head was
not supposed to move, which made the servo twitch — the "drill" effect.

## Decision

- `Head` remembers the angle it was last commanded to as `Option<u8>`.
- `Head::set_angle` returns immediately when the requested angle equals the
  stored one, leaving the pulse width untouched. The first command always
  writes, so the servo is initialised on the first loop (the `Idle` center).
- `Head::angle()` still reports `TURN_CENTER_ANGLE` before the first command, so
  the dashboard and the state logic are unchanged.
- The controller is untouched: it may keep asking for the same angle; the head
  ignores repeats.

## Consequences

- The head receives a new pulse only when it actually moves between `45`, `90`
  and `135` degrees; a steady state no longer jitters.
- New tests pin the behaviour: writing the same angle twice only writes the duty
  once, and staying `Idle` does not keep re-centring.
- `test_support`'s PWM double counts duty writes so the tests can assert this.
