# ADR-0017: Recalibrated thresholds and honest mp3 column

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

Watching the live log showed the state machine was poorly calibrated:

- `Action` fired from the *nearest* sensor within 30 cm, so a person off to one
  side could start the song; and because `Action` lasts the whole song, the log
  showed `Action` at 70-95 cm well after the trigger, which looked wrong.
- `Follow` reached out to 100 cm, which felt too far for a prop.
- The `mp3` column kept printing `track 1` forever after the first song, because
  it showed the *last* track played, not whether the player was playing now.

## Decision

- `Action` triggers only when **both** sensors see somebody within
  `ACTION_DISTANCE_CM` = 10 cm: the scary song is for a person right in front.
- `Follow` covers the nearest person within `FOLLOW_DISTANCE_CM` = 60 cm.
- Add `Reading::both_within(cm)` for the "both eyes" test used by `Action` and
  by the `PostAction` hold.
- The `mp3` column shows the track only while the state is `Action` (the song is
  playing) and `-` otherwise. `Track(None)` now renders `-` instead of
  `silent`.

## Consequences

- The song starts only for somebody directly in front and close, not for a
  person seen by a single side sensor.
- `Action` still lasts the song and hands over to `PostAction`; the thresholds
  only decide when it can start again.
- The log no longer claims `track 1` while nothing is playing.
