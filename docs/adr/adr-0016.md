# ADR-0016: Dedicated serial log reader with a clean Ctrl-C

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

`make logs` streamed the serial port with `cat` under `make`. Pressing Ctrl-C to
stop sent SIGINT to the whole foreground process group, so `make` itself was
interrupted and printed `make: *** [logs] Interrupt`, which looks like a crash
even though the firmware is fine. GNU `make` always reports its own
interruption; the only way to avoid it is to keep `make` from receiving SIGINT.

## Decision

- Add `tools/logs`: a Python tool (with `pyserial`, in its own `.venv` like the
  other project tools) that finds the USB serial port and streams it.
- While streaming it puts the terminal in a mode where Ctrl-C is read as a
  keystroke instead of SIGINT (`ISIG` off), restores the terminal on exit, prints
  `(stopped)` and returns status 0. Because no SIGINT reaches it, `make` exits
  cleanly with no error.
- `make logs` and `make probe` call `tools/logs`; the Makefile no longer uses
  `cat` or the earlier `serial` helper target.

## Consequences

- Stopping the logs is clean: `(stopped)` and a normal exit, never a `make`
  "Interrupt" message.
- The tool waits (up to ~20 s) for the port to appear, which also covers the
  moment right after `make probe` flashes the board.
- Ctrl-C during the first instants, before the tool disables signal generation,
  can still interrupt `make`; in practice the tool is ready within a second or
  two.
- This is a UX fix on top of ADR-0010/0011/0014/0015; the log format is
  unchanged.
