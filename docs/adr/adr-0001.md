# ADR-0001: Firmware layout and behavior state machine

- **Status:** Accepted
- **Date:** 2026-09-27

## Context

The prop must watch for people, follow them with its head, and play a scary
song when they get close. Behavior like this is easy to scatter across flags and
`if` chains, which becomes hard to read and maintain.

## Decision

- The firmware lives in the `firmware/` directory as a bare-metal `no_std`
  Rust project for the RP2040.
- Behavior is modeled as an explicit finite state machine with three states:
  `Idle`, `Follow`, and `Action`.
- The next state is a pure function of the nearest distance reported by the two
  side sensors, which keeps the logic small and testable.

## Consequences

- Transitions are easy to read and to test without hardware.
- New reactions must be expressed as new states or transitions, keeping the
  main loop a simple dispatcher.
