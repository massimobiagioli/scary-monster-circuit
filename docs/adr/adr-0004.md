# ADR-0004: Library/binary split for host-testable logic

- **Status:** Accepted
- **Date:** 2026-09-27

## Context

Bare-metal firmware is hard to test because it needs real hardware. We still
want fast unit tests for the behavior and the small drivers.

## Decision

- `firmware/` is a single Cargo package with two targets:
  - the **library** lives in `src/lib/` (root `mod.rs`, with `audio.rs`,
    `sensor.rs`, `servo.rs`, `state_machine.rs`) and is selected with
    `[lib] path = "src/lib/mod.rs"`.
  - the **binary** lives in `src/main.rs` and holds the RP2040 setup that wires
    the real hardware.
- The library depends only on portable `embedded-hal` traits, so it stays
  testable off the device.
- Unit tests run on the host with `make test`, using `cargo test --lib` and the
  host target.

## Consequences

- Behavior and drivers are tested without hardware.
- Hardware-specific code is isolated in `src/main.rs`.
- The source is grouped in clear subfolders: `firmware/src/lib/` for the logic,
  `firmware/src/main.rs` for the device wiring.
- The Makefile must run tests for the host target and firmware for the device
  target.
