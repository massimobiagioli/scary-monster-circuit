# ADR-0013: Post-action hold after the scary song

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

The behavior state machine picked a state purely from the current distance. As
soon as somebody stepped just past the 30 cm action range, the state dropped to
`Follow`, and another step forward re-entered `Action` and started the song
again. On the live dashboard this showed up as the state bouncing
`Action → Follow → Action` and the track restarting while the first scary song
was still playing.

## Decision

- Make `Action` last a fixed number of ticks, roughly the length of the song
  (`ACTION_DURATION_TICKS`, 200 ticks at the 50 ms loop period, about 10 s).
  While it lasts, distance changes do not pull the prop out of `Action`.
- Add a `PostAction` state, entered when the song ends. In `PostAction` the head
  follows the person like `Follow`, but the monster does not trigger again: it
  waits until the person leaves the 30 cm action range before it can act.
  Leaving the range releases it to `Follow` (within 100 cm) or `Idle`.
- Keep the state machine the single owner of this behavior: the countdown and
  the `PostAction` state live in the enum/struct, not in scattered flags in the
  main loop. `Controller` only reacts to entering `Action` (play once) and to
  `PostAction` (turn the head like `Follow`).
- The `probe` dashboard now reports `PostAction` too.

## Consequences

- The song plays to completion and is not restarted by small movements; it only
  replays after the person actually leaves the action range and comes back.
- The state no longer oscillates `Action → Follow → Action`, which matches what
  a person watching the prop expects.
- The state machine is no longer purely distance-driven: `Action` is
  time-driven, so its tests advance the tick count. The main-loop cadence
  (50 ms) is part of the contract and is documented on the constant.
